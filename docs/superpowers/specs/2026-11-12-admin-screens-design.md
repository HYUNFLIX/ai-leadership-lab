# 관리자 화면 개선 — 설계

날짜: 2026-11-12 · 대상: `lectures.html`, `crm/index.html`, `crm/visitors.html`, `js/assistant-panel.js`, 새 공통 파일

## 목적

관리자 화면 세 개(강의 이력·고객사·방문자)를 실제 규모(강의 188건)에서 쓰기 편하게 만들고,
화면마다 따로 복사돼 있는 로그인·메뉴·색상을 하나로 합친다.

두 단계로 나눠 각 단계가 끝나면 배포할 수 있게 한다. 각 단계는 별도 구현 계획을 가진다.

- **1단계 — 강의 이력 화면 사용성.** 로그인 코드는 건드리지 않는다.
- **2단계 — 공통 틀, 밝은 테마 통일, 고객사 화면 보강.**

범위 밖: 견적·세금계산서, 캘린더 연동, 가예약·확정 상태, 한 페이지 통합, 관리자 계정
2단계 인증(AWS 콘솔 설정), 백엔드 변경.

## 결정 사항

| 항목 | 결정 |
|---|---|
| 테마 | 세 화면 모두 밝은 테마로 고정. PC의 다크 모드 설정을 따라가지 않는다 |
| 구조 | 화면은 세 페이지 그대로. 로그인·메뉴·색상은 공통 파일로 분리 |
| AI 비서 패널 | 어두운 색 유지 |
| 삭제 | 확인 창 대신 "되돌리기" 알림(8초) |

## 1단계: 강의 이력 화면 (`lectures.html`)

### 화면 구성

위에서 아래로: 상단 메뉴 → 요약 줄 → 월별 추이(접기 가능) → 목록 도구줄 → 표.

지금의 "대시보드" 섹션과 "강의 등록" 섹션은 없앤다.

### 요약 줄

현재 필터(검색어·연도·월·입금상태)에 걸린 강의 기준으로 다섯 값을 항상 보여준다.

| 항목 | 계산 |
|---|---|
| 강의 | 건수 |
| 강의료 | `fee` 합 |
| 실지급액 | 실지급액 합 |
| 미수금 | 입금 여부가 `pending` 또는 `partial`인 강의의 실지급액 합과 건수 |
| 교육시간 | `duration` 합 |

실지급액은 저장된 `netPayment`가 있으면 그 값, 없으면 기존 식(`calculateNetPayment`)으로 계산한다.
일부입금은 받은 금액을 따로 기록하지 않으므로 전액을 미수금으로 센다(항목 이름 옆에 건수 표시).

미수금을 누르면 입금상태 필터가 새 값 "미수(대기+일부)"로 바뀐다. 다시 누르면 "전체"로 돌아간다.

### 월별 추이

선택한 연도의 1~12월 강의료 합을 막대로 보여준다. 연도가 "전체"면 숨긴다.
막대에 마우스를 올리거나 누르면 그 달의 건수·강의료·실지급액을 보여준다.
접기 버튼이 있고, 접힘 상태는 `localStorage['ailab_lectures_chart']`에 기억한다.
외부 차트 라이브러리는 쓰지 않는다(인라인 SVG).

### 목록

- 처음 열 때 연도 필터의 기본값은 올해(한국시간). 올해 데이터가 없으면 "전체".
- 표 머리글은 스크롤해도 상단 메뉴 바로 아래에 고정된다(1281px 이상. 그보다 좁으면 표가
  가로 스크롤을 쓰므로 고정하지 않는다). 모바일 카드 목록은 지금 그대로다.
- 도구줄: 검색, 연도, 월, 입금상태, [+ 강의 등록], 그리고 "더보기" 안에 Excel 다운로드·
  JSON 내보내기·JSON 가져오기. 상단 메뉴에서 내보내기·가져오기 버튼은 뺀다.
- 행 버튼: 수정, 복제, 삭제. 버튼은 `data-id`와 이벤트 위임으로 동작한다(인라인 `onclick`에
  id를 넣지 않는다).

### 등록·수정·복제

지금의 수정 창 하나를 세 용도로 쓴다.

| 용도 | 여는 방법 | 창 제목·버튼 | 저장 |
|---|---|---|---|
| 등록 | [+ 강의 등록] | "강의 등록" / "등록" | `POST /lectures` |
| 수정 | 행의 수정 버튼 | "강의 수정" / "저장" | `PUT /lectures/{id}` |
| 복제 | 행의 복제 버튼 | "강의 등록" / "등록" | `POST /lectures` |

복제는 강의명·고객사·대상·계약주체·교육장소·교육시간·강의료·세금공제를 채우고,
강의일자는 비우고, 입금 여부는 "대기", 기타사항은 비운다.

고객사·계약주체·교육장소·강의명 입력칸은 기존 강의에서 많이 쓴 순서로 값을 제안한다(`<datalist>`).

### 삭제 되돌리기

삭제 버튼을 누르면 확인 창 없이 바로 `DELETE /lectures/{id}`를 보내고 목록에서 뺀다.
"삭제했습니다 · 되돌리기" 알림을 8초 보여준다. 되돌리기를 누르면 삭제한 항목을 `id`와
`createdAt`을 그대로 넣어 `POST /lectures`로 다시 만든다(기존 API가 `id`·`createdAt`을 받는다).
8초가 지나거나 페이지를 떠나면 되돌릴 수 없다.

### 고칠 문제

- Excel 다운로드가 검색어를 무시한다 → 화면에 보이는 목록(필터·정렬 그대로)을 내보낸다.
- `title="..."` 속성에 넣는 값이 따옴표를 이스케이프하지 않는다 → 속성용 이스케이프를 쓴다.
- 알 수 없는 입금 여부 값이 이스케이프 없이 출력된다 → 이스케이프한다.
- 알림 문구를 `innerHTML`로 넣는다 → `textContent`로 넣는다.

### 파일

| 파일 | 내용 |
|---|---|
| `js/lecture-stats.js` | 순수 계산: 요약, 월별 합계, 자동완성 후보. 브라우저와 Node 테스트가 함께 쓴다 |
| `js/test/lecture-stats.test.mjs` | 위 계산의 단위 테스트 |
| `lectures.html` | 화면 구성, 창, 삭제 되돌리기, 버그 수정 |

`js/lecture-stats.js`가 내보내는 함수:

- `netPaymentOf(lecture): number`
- `summarize(lectures): { count, sumFee, sumNet, sumHours, outstandingCount, outstandingNet }`
- `monthlyTotals(lectures, year): Array<{ month: '01'..'12', count, sumFee, sumNet }>` — 항상 12개
- `suggestions(lectures, field, limit = 50): string[]` — 많이 쓴 순, 같으면 가나다순

## 2단계: 공통 틀과 밝은 테마

### 공통 파일

| 파일 | 내용 |
|---|---|
| `css/admin.css` | 색·글꼴·버튼·카드·입력칸·표·상단 메뉴·알림·로그인 화면. 밝은 테마 하나 |
| `js/admin-shell.js` | 로그인 화면, 토큰 관리, API 호출, 상단 메뉴, 알림 |

`js/admin-shell.js`는 `window.AilabAdmin`을 제공한다.

- `ready(callback)` — 로그인된 뒤(이미 로그인돼 있으면 즉시) 호출한다. 각 화면은 여기서 데이터를 불러온다.
- `api(path, options): Promise<object>` — 토큰을 붙여 호출한다. 401이면 토큰을 한 번 갱신해
  한 번만 다시 시도하고, 그래도 401이면 로그아웃 처리 후 로그인 화면을 띄운다.
- `toast(message, { type, actionLabel, onAction, duration })`
- `signOut()`, `user`(`{ email }`)

각 화면은 `<script src="/js/admin-shell.js" data-page="lectures | clients | visitors" defer>`로
불러온다. 공통 틀이 상단 메뉴(강의 이력 · 고객사 · 방문자, 이메일, 로그아웃, 768px 이하에서는
메뉴 버튼)와 로그인 화면을 그린다. 로그인은 지금과 같은 Cognito `USER_PASSWORD_AUTH`이고
첫 로그인의 새 비밀번호 설정(`NEW_PASSWORD_REQUIRED`)을 세 화면 모두에서 지원한다.

토큰 저장 위치(`localStorage['ailab_tokens']`)와 형식은 바꾸지 않는다. 홈페이지의 방문 집계가
이 값으로 관리자를 구분하기 때문이다.

### 화면별 변경

- **강의 이력**: 자체 헤더·로그인·토큰 코드를 지우고 공통 틀을 쓴다. 색상 변수는 `css/admin.css`로
  옮기고, 다크 모드용 `prefers-color-scheme` 블록을 지운다.
- **고객사(`crm/index.html`)**: 밝은 테마, 공통 틀 사용. 삭제 되돌리기(강의와 같은 방식),
  고객 목록 내보내기(Excel에서 열리는 CSV, UTF-8 BOM), 팔로업 D-day를 한국시간 기준으로 계산.
- **방문자(`crm/visitors.html`)**: 밝은 테마, 공통 틀 사용.
- **AI 비서 패널**: 자체 토큰 코드를 지우고 `AilabAdmin.api`를 쓴다. 색은 그대로.

### 검증

- 로그인 흐름은 인증 서버 응답을 가로채 시험한다: 로그인 성공, 비밀번호 오류, 첫 비밀번호 설정,
  만료된 토큰 갱신, 갱신 실패 시 로그인 화면, 401 한 번 재시도.
- 세 화면을 가짜 API로 1440px·390px에서 확인한다.
- 실제 계정 로그인은 배포 후 사용자가 확인한다.

## 공통 원칙

- 프레임워크나 빌드 단계를 넣지 않는다. 지금처럼 정적 파일이다.
- 표시하는 값은 모두 이스케이프한다.
- 단계마다 기존 기능(등록·수정·삭제·필터·정렬·Excel·JSON 가져오기·모바일 카드 목록·AI 비서)이
  그대로 동작하는지 확인한 뒤 끝낸다.
